# Portfolio research and risk service

`liki.portfolio` is a deterministic **research-only** allocator and stress engine. It accepts only synchronized, common-clock simple strategy returns, validates the complete strategy universe at every observation, applies declared return and covariance shrinkage, and applies hard strategy/liquidity/asset/venue and optional one-way turnover constraints before considering allocation variance. It has no order, venue, account, or real-money execution API.

`PortfolioService` persists each analysis as a content-addressed artifact and binds it to the authenticated `research` identity, data/evidence references, an immutable event, a portfolio model identity, and a portfolio-level trial-family identity. It records a same-constraint equal-weight simple challenger with every material allocator. Portfolio construction therefore cannot reset component-strategy multiplicity.

Risk views include gross and directional exposure, leverage, strategy/asset/venue concentration, measured factor and common-dependency exposure, marginal component risk, expected shortfall, compounded-equity drawdown, tail co-movement, correlation instability, capacity/liquidity estimates, explicit scenario loss paths, and optional seeded block-bootstrap risk-of-ruin intervals. Each strategy supplies its declared liquidity-stress loss fraction; liquidity-at-risk is not fabricated from an unrelated allocation cap. When available, `CapitalState` records reporting-currency withdrawable, margin-encumbered, trapped, and withdrawal-delayed capital with a valuation artifact; cross-venue transfer is never assumed during stress.

Scenario and reverse-stress recovery, slippage, funding/borrow, collateral/FX, venue-default, and liquidity-feedback assumptions are explicit input fields. `venue_default_loss` represents the exposed loss before the declared recovery fraction. Reverse stress searches the smallest severity of a declared plausible shock combination that breaches a declared loss target, or records that the maximum declared combination cannot do so, with dominant paths and uncertain assumptions. PnL attribution treats a residual beyond the supplied tolerance as non-authoritative rather than silently zeroing it.

The allocation output retains the requested method: inverse-volatility is projected onto the declared hard constraints rather than silently substituted with minimum variance. Every material allocator is compared with a constrained equal-weight challenger under the same restrictions. Expected shortfall and maximum drawdown use the registered canonical metric IDs and versions; custom tail/correlation diagnostics are descriptive risk observations, never gate substitutes. Turnover has the explicit one-way notional-change-over-equity convention and is `NOT_APPLICABLE` when no prior allocation is provided.

The readiness-packet API only stores evidence for a `READY_FOR_MICROLIVE` assessment; all resulting rows and artifacts are fixed to `RESEARCH_ONLY`. It cannot promote a strategy, change paper settings, or enable real execution. The required packet fields bind lineage, code/data/evaluator, statistical limitations, sealed history, forward-paper/TCA evidence, portfolio contribution, tail/ruin, capacity/liquidity, model risks, and explicit failure reasons.

## Persistence and integration

Migration `015_portfolio.sql` adds append-only `portfolio_models`, `portfolio_evaluations`, `portfolio_trials`, `portfolio_strategy_status_events`, and `portfolio_readiness_packets`. Each has authenticated read and research-only insert RLS, provenance binding, immutable history, and event linkage.

The parent scheduler/server should register handlers and outward notification routing for aggregate kinds `portfolio_model`, `portfolio_evaluation`, `portfolio_trial`, `portfolio_strategy_monitor`, and `portfolio_readiness_packet`. Current `liki_can_mutate_aggregate` safely routes unlisted kinds to `research`; a future core hardening migration should enumerate these kinds explicitly before any role expansion. No parent integration may translate this service into an execution path.
